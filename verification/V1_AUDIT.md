## 实际数据验证

MTBBench 完整导入 **183 题、40 位患者**。其中 152 题有多种文档类型；当前文本适配器没有独立文献与药物文档，药物信息可能出现在病例正文。结构覆盖计数只表示显式输入，不作为 Agent 的重要性标签。它承担病例异构资料整合的主评测，而药物、文献模块使用对应补充任务。

CIViC-Fact 完整导入 **12476 条、1409 个来源组**，原生标签 SUPPORTS / REVISIONS / NEI。修复后原始主张结构化字段覆盖为：基因变异 9365 条、癌种 11555 条、药物 8446 条。其单证据核验任务承担组件评测，不能将这些主张字段当成独立患者模态或已证实的来源事实。713 条 unassigned 数据保留原状态，正式实验只按声明的 split 选样本。

独立同文章检索适配得到 **1140 个查询**；人工跨度覆盖阈值 0.75，合并重复行 398。排除行按原因分别为 NEI 106、冲突标签 40、缺失文章/跨度/相关段落 23，详细审计留在本地准备结果。两个抽样查询跑通 BM25 与实体重排。

正式内容模拟联调：旧五系统 MTB 70 / 70、CIViC 45 / 45；第一版新增流程 MTB **183 / 183**、CIViC **9 / 9** 全部完成。对 MTB 全输入工程检查不计算测试集正确率。

## 本轮确实发现并修复的风险

1. 重复来源在检索截断之前占满候选池：去重提前，保留同一来源的不同段落，消融开关仍可关闭。
2. 可选补证占用最终 Decision 的预算：补证前保留必需调用；保守 v1 固定关闭自动补证。
3. 专业节点未收到原生核验标签定义：统一向每个节点传递任务标签和语义，保留 REVISIONS。
4. 同患者用不同 group_id 绕过划分：导入和评测核对 patient_id 与分组一致性。
5. 截断的 HTTP 200 响应丢失供应商用量：失败轨迹保留已报告 token 与费用，估算和真实报告分开。
6. 结构修复缺少失败响应：传入有长度上限的实际失败内容和校验错误。
7. 新版 CIViC Text(type='claim') 对象被旧表格解析器忽略：同时支持真实 dict 格式、单数 disease、therapies 列表，复合变异保留原始问题，gold revised_claim 继续隔离。
8. 原 120000 token 总上限导致 6 / 183 长病例工程中断：v1 与其全部对照统一调整为 200000，全量重跑 183 / 183 完成。该数是整个病例的总预算上限，不是单次上下文要求，也不是固定消费；真实 API 先做费用试跑。
9. v1 范围和入口分散：提供固定 profile、输入覆盖审计、三系统小试及十一配置消融计划，旧大型实验保持独立。
10. 终端证据图与输入边界不足：加入最终决策引用边，缺依赖/未审核远程处理在运行前明确拦截，网页继续使用受保护的 /v1 契约。

## 科学与部署验收边界

商业 LLM 调用为 **0**，模型回答均为模拟器。软件测试通过说明数据、流程、预算和接口按契约运行。医学答案质量、引用的语义支持、各 Agent 的效果及 token 成本曲线由 TASK.md 中的真实开发集与盲审流程确认。

当前是单进程、共享 Bearer 的可信研究工作区。脱敏声明是输入契约，实际脱敏由上传前审核完成；公开多租户部署和自动隐私识别另行验收。现有工程可以直接接真实 API，保持失败记录、来源版本、冻结协议和新旧结果隔离。
