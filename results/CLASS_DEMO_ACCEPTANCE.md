## 输入截尾修复证据（本地重放，不调模型）

`scripts/fragment_truncation_audit.py` 按基准提交 56492fd 的前缀走法（`fragment_chars=600`、每文档最多 8 段）重放了 `data/mtbbench` 的全部输入：

- 病例 183 个，其中 **126 个**至少有一份文档被截掉尾部；文档 1051 份中有 181 份被截。
- 看不见的原文共 310902 字符，占全部输入字符（1980042）的 **15.7%**。

现行 `fragment_documents()` 先把每份文档整篇切成记录级候选（候选数＝上表文档的真实段数，不再有“永远不可见的前缀之外内容”），再按问题、最新临床事件与分子/病理关键字段挑选送入子集；每个节点把自己收到的 `evidence_ids` 与覆盖信息写进结果行，就是上一节那张表。
换句话说：修复的是“候选层面的截尾”，送入层面仍然受预算约束，并且现在会在页面上明说。

## 本轮修了什么（可在代码与测试里核对）

- 片段规划改成整篇文档的记录级候选 + 按问题/最新临床事件/关键字段选择，换行只前进 1 字符；`tests/test_v1_fast.py` 里有对应的 4 条回归（跨行不切字、整篇候选、预算截断、未送入的 id 不可引用）。
- 原始来源、可见文档、实际送入片段三个概念分开记录：每个节点写自己的 `evidence_ids` 与 `evidence_coverage`，页面角色卡片读的就是这两个字段，不再出现“模型读了全文”这类描述。
- claims-v1 协作协议：主张带稳定 `claim_id`/`author_role`，后序声明 `used_claim_ids`，Verifier 逐主张给 `confirmed/corrected/rejected/insufficient`，Decision 给采用与排除；层面越权（例如专业角色直接下结局判断）由 `ROLE_SCOPES` 当场拒绝，回归在 `tests/test_claim_scopes.py`。
- 计划文件不再手抄配置：`scripts/make_class_plan.py` 从 `profiles.v1_class_config()` 写出计划并断言相等，`tests/test_v1_contract.py` 检查每个计划的 ceiling 与它 `reference` 的 profile 一致（历史计划显式列入 frozen 名单）。
- demo 只认真实 provider：`ONCOFUSION_DEMO_REQUIRE_REAL=1` 时缺 API 直接启动失败；页面模式取结果行的 `simulated`；回放白名单校验 `(study, treatment)` 与 case id 字符集（`tests/test_demo_app.py` 覆盖了 `../unapproved` 逃逸）。
- 用量与失败分母：逐角色累加所有修复调用，`/v1/library?include_failed=true` 一并返回 `.failed.json` 行并可筛完成项。
- CI：core 走 native 后端，LangGraph 契约单独一个 job；container 断言 `/app` 含「主张与核验关系」「执行顺序」且 demo 配置是 v1_class/claims-v1。
